# 『安全なWebアプリケーションの作り方 第3版』8章 実習用リポジトリ

本書の【8.4 SCAの利用】から【8.8 手動脆弱性診断と本番リリースゲート】までの実習で使うサンプルプロジェクトです。チケットの抽選申込みを受け付けるウェブアプリケーションに、GitHub Actions でSCA、SAST、DASTを順に組み込んでいきます。

## 注意

このリポジトリのアプリケーションには、学習のために**意図的な脆弱性**が含まれています。

- 本番環境や、インターネットから誰でもアクセスできる場所で動かさないでください
- 作成したリポジトリには、実習用のコード以外を入れないでください

## 使い方

1. このページの右上にある「Use this template」から「Create a new repository」を選びます
2. リポジトリ名を入力し（任意の名前で構いません）、公開設定を Public にして作成します
3. 以降の手順は本書の【8.4 SCAの利用】を参照してください

作成したリポジトリは、このテンプレートの内容をコピーした独立したリポジトリです。このテンプレートが後から更新されても、作成済みのリポジトリには反映されません。

## 構成

| パス | 内容 |
|---|---|
| `app/` | 実習用のウェブアプリケーション（Node.js、Express、EJS、SQLite） |
| `.github/workflows/ci.yml` | ユニットテスト、SCA、SAST、DAST を実行する CI |
| `.github/workflows/cd.yml` | 【8.7 CDの実装（オプション）】で使う CD |
| `.semgrep/` | SAST（Semgrep）の自作ルール |
| `.zap/` | DAST（ZAP）のルール設定 |
| `solutions/` | 各節の実習の解答パッチ（使い方は `solutions/README.md`） |

## 読む時期による違い

依存しているパッケージには、本書の執筆後も新しい脆弱性が公開されることがあります。そのため、実習の手順どおりに修正しても、本書に掲載したもの以外の脆弱性が検出される場合があります。その場合も、本書で説明する手順で内容を確認し、依存パッケージを更新してください。
